### Conventions (so all five match)
- **Where:** `app/ui/src/views/tools/studio/templates/<kebab-name>.graph.json`, listed in
  `app/ui/src/views/tools/studio/examples.ts` (`EXAMPLES`: id, label, one-line blurb naming the Studio pieces it
  teaches). The start screen shows them under "Example modes"; the tour opens Infection.
- **Built by script:** `app/src-tauri/src/tools/studio/make_examples.py` (one function per mode, a tiny DSL:
  `m.part(note)` starts a comment box/row, `m.n(id, type, params, below=)`, `m.w("a.pin", "b.pin")`,
  `m.flow("a", "a.true", "b", ...)`, `m.var`, `m.func`; `m.graph = "<fn id>"` for a Function's tab). Edit the
  script, not the JSON: run `python3 make_examples.py`, then lay out only the examples:
  `cd app/ui && node scripts/tidy-studio-templates.mjs infection.graph.json ...` (the script now takes names).
  P5: your three are the functions `koth()`, `oitc()`, `juggernaut()`; I won't touch them from now on.
- **Mode ids / names:** snake_case id = the name (`king_of_the_hill`), a fixed uid per example (a new one is made
  when a player creates a mode from it), description ≤ 60 characters, game settings in `mode.settings` (only
  the Set Setting cvars: mp_freeforall, mp_round_infinite, mp_autoteambalance, mp_limitteams...).
- **Size and notes:** 25-90 nodes (a test checks), at least 3 comment boxes; every part starts with a note in
  plain, friendly US English saying what the part does and why (no slash, star or quotes: the label rules).
  Node ids are short words (`pk`, `respawn`, `win`), not n1/n2. Functions for anything used twice.
- **Bots:** Bots nodes where the mode needs them (Don't Buy when buying is off, goals for objectives).
- **Checks each must pass before it ships:** Quick check with no problems at all (not even warnings),
  Compile with no warnings (`examples_tests.rs` does both builds with the real amxxpc), a Test run that passes
  (my client: scratchpad `sim/gb.py` + `tr.sh`; or the Studio's Test run button), and a long play on a sim with
  12 bots (I use 8 minutes; `sim/longplay.sh <graph> <map> <secs> <bots> <port>`: installs into a sim copy
  through a Tools dev server, plays with game logging on, keeps the logs, deletes the clone) reading the game
  log for the rules (team changes, round ends, kills) and the AMXX log for errors.
- **Tests:** `examples_tests.rs` (Rust) and `scripts/studio-help.test.ts` (UI) cover all five by name; if you
  rename or add one, update both.

## For P5's docs (2026-11-14): what users should know
**Data tables** (My mode > Data tables, + to add; click one to open its grid):
- A grid of values to look up: a gun list, prices, waves. Each column has a type: number, text, yes/no, an enum,
  a weapon (ak47, deagle, knife...) or an entity name. The **key column** names each row (keys must differ).
- **Paste or import CSV…** takes rows from a spreadsheet (commas or tabs; a first row with the column names is
  skipped; "Replace the rows there are" to start over); **Copy as CSV** goes the other way. Cells that don't fit
  the type are blanked (a weapon that isn't one becomes the knife).
- Nodes (category Data tables): **Get Row** (by key: Found, Row and every cell as a pin), **Get Cell** (a column
  of a row number; rows count from 0), **For Each Row**, **Find Rows** (row numbers where a column has a value),
  **Row Count**, **Row Keys**. Give Weapon now takes a weapon's name (and spare bullets) wired in, so a table can
  say which gun.
- Limits: 16 tables, 12 columns, 256 rows, text cells 48 letters, 6000 cells per mode; the Quick check says when
  one is over. Tables are built into the plugin, so reading them costs almost nothing.
- Showcase: Gun Game Lite's gun list is now the **Guns** table (Level, Gun, Spare bullets): reorder guns there.
**Live tweaks** (while a Playtest runs, debugger panel > Live values):
- **Change** next to a variable (number, yes/no, text, enum; the mode's, a player's or a team's) sets it in the
  running game at once, no recompile. The log says "You set Bonus to 42". Bad values are refused with why (not
  a number, text with odd characters).
- **Use as start value** copies the live value into the graph as the variable's start value.
- Only a Playtest (the debugger's build) takes changes; an installed mode never does.
**Also new for the docs:** the delete question (Replace with…, Remove it and its nodes, Remove and keep the
nodes; Find uses; one Undo; something nothing uses goes at once), the Timeline cost warning (a Timeline played
per player is up to 32 copies), and a playing Timeline's time, direction and values in the debugger.
**My draft of the Studio docs** (uncommitted in site/docs.html when you took over): first mode tutorial, node
help, event graphs and custom events, Timelines, data tables, bots and creatures, server command safety, the

## + Add pin, and wireable For Each / Pick Random (2026-11-14)

  − is refused at the minimum or while the pin it would remove is wired (a note shows for 3 s). The other count
  settings (Say / Choose replies, Start Vote, Format Text) don't change pins, so they get no button.

  used-bits mask is computed in u64 and fits g_lsgLeft's cell; `free[32]`. Test: x2_pins_tests.rs (12 Sequence
  outputs + 20 Multi Gate outputs, generate + amxxpc). The reference cards say "N shown; add up to M with + Add pin"
  (gen-reference.mjs addPinNote, swept into 4470b4bd).

  g_lsgLeft like For Each with Break). Nothing wired: the settings, as before. Shared loop head: gen.rs `each_head`.
