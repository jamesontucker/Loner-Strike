## Rule from Y (2026-11-13): touch only your own server processes
- Never attach a debugger (`winedbg <pid>`, `attach`, DebugBreakProcess, anything that puts a thread into another
  process) to a running hlds under CrossOver: the injected thread starts at 0xfff4fadc and kills the server.
- Stop, signal or inspect only the processes your own script started: by the PID you got when you started it, or by a
  pattern that names your own sim folder (`Sim[\\/]<yours>[\\/]hlds.exe`). Never by name (`hlds.exe`, `winedbg`) and
  never by "the newest process". Before a start, make sure your port is free (`lsof -nP -iUDP:<port>`).
- Stacks and crashes without a debugger: `drive_c/Loner-Strike/Sim/crashes.log` (every crash in the bottle, full
  winedbg report), and with fork builds from ls-creatures `f351765` on, `cstrike/ls_crash*.log` and
  `cstrike/ls_watchdog.log` in the server folder.

## P5: editor backend performance (PerfAudit.md #1d, #1e, #7, #10), 2026-11-13
- **No whole-map copies per command.** History notes touched brushes and entities on the document
  (`MapDocument::touched`, `touch_brush` also notes the entities a brush left or joined); `Session::track` reads that
  instead of comparing and cloning every brush (`prev` is gone). `apply`/`apply2` no longer clone all entities.
  `Session.bounds` keeps each brush's bounds (the document answer recomputed all of them every time).
- **Off the lock:** meshes (`MeshSnap`: the changed brushes and texture sizes copied under the lock, built after) and
  autosave (`AutosaveSnap`: a document copy under the lock, serialized and written after; one writer at a time).
  Checks already ran off it (the Checks agent).
- **Document changes, not the document:** every `cmd`, `cmd2`, `undo`, `redo` and `history/jump` answers with
  `changes` (`changes_json`: changed/removed brushes and entities in the document's shape, plus groups, world,
  settings, bounds, stats; shape agreed in ParityA.md); `GET doc?doc=&since=` gives the same. The page patches its copy
  (`applyChanges`, unchanged objects keep their identity) or catches up from its own revision (`catchUp`).
  `doc.revision` = the revision of the content the page holds (`mergeState` no longer moves it or `docId`).
- **Checks:** 1.2 s debounce (was 350 ms), wait while a command or drag is on its way, and not again for a
  document revision (and limits) already checked.
- **Polling:** outside changes by long-poll (`GET state?wait=<rev>&doc=`: answers when the document moves on or after
  25 s, checked every 200 ms on the server with try_lock, only while the page is visible); app-wide: `/api/state`
  every 5 s unless a game or server is up (2 s), the server list every 30 s when there are none, React Query
  staleTime 30 s (a focus no longer refetches everything).
- **Measured** (release dev server, br_valley 5426 brushes / 751 entities, same load ~19, back to back;
  scratchpad perf/measure.py, before-bin/after-bin):

  | page catching up after it (cmd + meshes + document) p50 / p95 | 27.7 / 30.9 ms | 3.6 / 4.2 ms |
  | document sent per edit | 673 KB | 0.8 KB |

  | autosave | 150-170 ms (lock held) | 90-100 ms (lock free) |
  | idle editor page, requests a minute | 40 (state every 1.5 s) | 2 (one long-poll per 25 s) |
