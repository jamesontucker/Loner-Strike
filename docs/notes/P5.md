## 2026-11-13 — big maps, the Map editor crumb, the camera in the app
**Big maps (br_valley: 2974 brushes, 233 entities, ~8000 units across)**
- Unpicked brushes are drawn merged: one mesh per texture and one set of outlines for world brushes and one for
  entity brushes (`editor/MergedBrushes.tsx`), rebuilt only when the brushes, what's picked or hidden, the cordon
  or the drawing style change. Each brush keeps an invisible mesh of its own, so clicking still finds the brush and
  its face (checked on br_valley). Picked brushes are drawn one by one, as before (they move with the gizmo).
  Dev builds compare with `editor-dev.html?nomerge` (the old way).
- Measured (Playwright, 1440×900, flying with right mouse + D for 3 s; "fps" = the page's animation frames while
  flying; draws = WebGL draw calls per frame; Chromium headless draws in software, WebKit on the GPU):

  | map | browser | before: fps / draws | after: fps / draws |
  |---|---|---|---|
  | br_valley | Chromium | 8 / 8572 | 21 / 530 |
  | br_valley | WebKit (the Mac app's engine) | 36 / 7628 | 61 / 557 |
  | ls_outpost | Chromium | 33 / 725 | 30 / 238 |
  | ls_outpost | WebKit | 61 / 728 | 61 / 241 |

  The remaining ~500 draws on br_valley are entities (boxes/models, outlines, target lines). Loading br_valley:
  ~1.8 s from the click to the first picture, in both.
- Camera on big maps: flying speed scales with the map (×1 up to ×4: the map's size / 3000 units; the speed note shows
  real units per second, e.g. 1400 u/s at step 4 on br_valley); the near plane grows with the map (depth stays sharp
  at the far end); the far plane was already 8× the map's half-diagonal. F frames big selections from far enough.
- Tests: `tests/editor-perf.spec.ts` pastes a generated 3000-brush map and checks under 600 draws and smooth flying;
  `tests/editor-nav.spec.ts` (nothing covers any pane; right mouse + W flies with a text box focused; Single, Quad).
  Run with the tools dev server: `LS_VITE_PORT=<port> npx playwright test tests/editor-perf.spec.ts tests/editor-nav.spec.ts`.
- A selected giant brush: left-dragging one of its faces pushes/pulls it (P2's tool), as before; right mouse looks and
  flies whatever is picked.

**Map editor crumb (02e64c5)**: the open map is its own address (`editor:<map>`), so the "Map editor" crumb goes to the
start screen after the unsaved-changes question (Leave goes, Cancel stays) with "Back to <map>"; Back, Alt+← and the
mouse's back button return to the map. Alt+← is Back in the editor too (common/shell.tsx skipped it there; the
editor's arrows nudge without Alt). Checked in the browser on tools-dev.html.

**Camera in the app (f38f421)**: couldn't reproduce in Chromium or WebKit (Playwright). Likely cause: WebKit doesn't move
focus on a right-click, so a focused search box kept WASD. Fixed both ways (a press in a view takes focus; keys are
the camera's while looking). If it still fails in the app: swap `PaneView` back for drei's `View` in EditorScene and
compare (PaneView only exists so the 3D pane doesn't go blank with a dock on the left).

**Dev server trick**: `LS_DEV_PICK=<file>` makes a test-build dev server answer the file dialog with that file (e.g.
`maps-src/br_valley/br_valley.map`), so big maps open in a browser.

## Requests from QA (2026-11-12, real tests; full report docs/notes/QA.md)
1. **[High] RMF/JMF import moves slanted brushes (leaks / broken brushes on real maps).** `editor/rmf.rs` `make_brush`
   (≈line 178): `tidy()` is applied to every normal component, rounding non-axis normals to 1/1024; with `tidy(dist)` the
   plane turns about the world origin, so far from the origin faces move up to several units. Measured against the
   source: regamedll_test_map_v8.rmf 154/760 brushes off by >0.1 u (worst 2.7 u), pmk_m1 47/172 (2.3 u), pmk_m3 104/308
   (9.3 u). Result: regamedll_test_map and pmk_m1 leak, pmk_m3 + aim_stadium get "Illegal Brush", de_kobbl has 52 brushes
   our own checks call broken and one with no polygon at all (bounds ±1.79e308 in `GET doc`; SDHLT: "brush outside world").
   The same RMFs written with Hammer's stored plane points (QA's converter) compile with no leak and no illegal brush.
   Fix idea: snap only near-axis normals (|c| within ~1e-6 of 0/±1), otherwise keep the file's plane points (RMF/JMF store
   three per face) as the .map points; and drop/repair a brush that ends up with no polygon instead of keeping it.
2. **[Medium] RMF spawnflags: when an object has both a `spawnflags` key and Hammer's flags field, the key wins; Hammer
   uses the flags field.** regamedll_test_map: func_rotating 257→1 and 129→1, func_breakable 2→6 (6 adds "Pressure").
   The map's own shipped BSP has 257/129/2.
3. **[Low] Non-ASCII entity text is destroyed on import**: game_text "Фаза - #1" (cp1251 bytes in the RMF) becomes
   "���� - #1" (U+FFFD). Keep the bytes (latin-1 round trip) instead of lossy UTF-8.
4. **[Medium] Imported RMF/JMF maps get no WADs** (Hammer/J.A.C.K. keep them in the editor config): every texture is
   "missing" and the compile fails with ~70 problems, but the notes only mention cameras. Say so in the notes and offer to
   pick WADs that contain the map's textures (game folders + the file's folder).
   Also the Project panel lists a WAD beside the project ("A texture file in the project's folder") but live checks and
   the compile don't look there (compile: "aren't on this computer"). (Compile side: P4.)
5. **[Medium] Live checks count func_detail as entities/models**: de_kobbl shows "1137 entities; a map can hold 1024" and
   "731 brush entities; the limit is 511", but 505 are func_detail, which SDHLT merges into the world.
6. **[Low] Hidden visgroups are imported shown and compiled** (de_kobbl has 4 hidden "Version …" sets). The note says so;
   consider importing them hidden (and leaving hidden sets out of the compile, like J.A.C.K.'s "visible only").
7. **[Low] `POST import-other` ignores `LS_DEV_PICK`**, so File > Import of RMF/JMF can't be tested in the dev server or by

9. UI findings (Playwright, WebKit + Chromium):

## 2026-11-13 — QA's requests: real Hammer/J.A.C.K. imports fixed
- **[QA-1] geometry drift, fixed** (`editor/rmf.rs`): faces are built from Hammer's three stored plane points (RMF),
  exactly, in f64 — what Hammer writes into a .map; J.A.C.K. faces from three well-spread corners (its stored 32-bit plane
  gave more illegal brushes on real maps, tried and measured). No normal is ever rounded; only a coordinate within
  0.001 of a whole unit is snapped. Faces that don't touch the solid are dropped, a brush with no closed shape left is
  refused and counted in the notes. Against QA's reference .map (Hammer's own points): pmk_m1/2/3 worst 0.0001 u,
  0 brushes over 0.001 u (were 47/9/104 brushes, up to 9.3 u). Test: a slanted wedge 4000 u out keeps its plane to 1e-6.
- **[QA-2] spawnflags**: the editors' own flags field wins; a stale "spawnflags" key is dropped (and none written for 0).
- **[QA-3] non-ASCII text**: UTF-8 when it is, else decoded from the old Windows code page (Cyrillic cp1251 when the
  high bytes run in Cyrillic letters, else cp1252): "Фаза - #1" survives. **P4:** the compile writes the .map as UTF-8;
  GoldSrc clients show text in their own code page, so Russian text in game_text may need writing back as cp1251.
- **[QA-4] WADs on import** (`tools/editor/workspace.rs` `find_wads`): the map's own WAD list is kept, then the fewest
  WADs that hold its textures are added, from the file's folder first, then the game's folders; the notes say which, which
  are named but missing, and how many textures aren't in any WAD here. **P4:** live checks and the compile still only look
  in the game folders (not the project's/file's folder), so WADs beside a map need copying into cstrike (or the compile
  should look beside the project too).
- **[QA-5] live checks**: func_detail no longer counts toward the entity / brush-model limits (SDHLT merges it into the world).
- **[QA-7]** `POST import-other` answers with `LS_DEV_PICK` on dev servers.
- **[QA-8]** the Tools dev server keeps everything (editor recent/autosave/backups, prefabs, Studio) in its temp folder:
  `sys::app_dir()` takes `LS_APP_DIR` in test builds, and devserve sets it to `$TMPDIR/ls-tools-dev` unless given.
- **[QA-9]** face drag: dragging a picked floor's top face up in 3D works (Chromium, Unreal preset: 16 → 208 units).
  Note: with the Unreal navigation preset, F frames the selection; Z does nothing (QA pressed Z first). Tie to entity
  from the menu/palette now picks the new entity. Outliner: a search or filter opens the folders its matches are in; the
  section toggles have names ("Fold Point entities").
- Not done: [QA-6] hidden visgroups still import shown (noted on import); arrow-nudge after a Move drag in Top (not
  reproduced yet); option-row height jump; float noise in shown sizes from vertex edits.
