## 2026-11-13 — big maps, the Map editor crumb, the camera in the app
**Big maps (br_valley: 2974 brushes, 233 entities, ~8000 units across)**
- Unpicked brushes are drawn merged: one mesh per texture and one set of outlines for world brushes and one for
  entity brushes (`editor/MergedBrushes.tsx`), rebuilt only when the brushes, what's picked or hidden, the cordon
  or the drawing style change. Each brush keeps an invisible mesh of its own, so clicking still finds the brush and
  its face (checked on br_valley). Picked brushes are drawn one by one, as before (they move with the gizmo).
  Dev builds compare with `editor-dev.html?nomerge` (the old way).
- Measured (Playwright, 1440×900, flying with right mouse + D for 3 s; "fps" = the page's animation frames while
  flying; draws = WebGL draw calls per frame; Chromium headless draws in software, WebKit on the GPU):

  | map | browser | before: fps / draws | after: fps / draws |

  | br_valley | Chromium | 8 / 8572 | 21 / 530 |

  | ls_outpost | WebKit | 61 / 728 | 61 / 241 |

  The remaining ~500 draws on br_valley are entities (boxes/models, outlines, target lines). Loading br_valley:
  ~1.8 s from the click to the first picture, in both.
- Camera on big maps: flying speed scales with the map (×1 up to ×4: the map's size / 3000 units; the speed note shows
  real units per second, e.g. 1400 u/s at step 4 on br_valley); the near plane grows with the map (depth stays sharp
  at the far end); the far plane was already 8× the map's half-diagonal. F frames big selections from far enough.
- Tests: `tests/editor-perf.spec.ts` pastes a generated 3000-brush map and checks under 600 draws and smooth flying;
  `tests/editor-nav.spec.ts` (nothing covers any pane; right mouse + W flies with a text box focused; Single, Quad).
  Run with the tools dev server: `LS_VITE_PORT=<port> npx playwright test tests/editor-perf.spec.ts tests/editor-nav.spec.ts`.
- A selected giant brush: left-dragging one of its faces pushes/pulls it (P2's tool), as before; right mouse looks and
  flies whatever is picked.

**Map editor crumb (02e64c5)**: the open map is its own address (`editor:<map>`), so the "Map editor" crumb goes to the

### Round 2 done (P5, 2026-11-13)
1. **Push/pull in Chromium — fixed.** Not a Chromium event problem: QA's box has a corner (-64, 64) on the starting 3D
   camera's line, so the middle column of the view runs exactly along that vertical edge. Chromium gives the exact
   middle pixel (pointer 0,0) and three.js's per-triangle test slipped between the two faces' triangles, so the ray hit

   through is the hit, the point is put exactly on that face (so the face still lands on the grid). QA's m-push test
   now passes in both engines with the same result. Test: `tests/editor-push.spec.ts` (Chromium, the exact case: click
   the middle to pick, drag the middle, "Move face", whole-number bounds).

### Mode map kits, the editor side (P5, 2026-11-13)
Follows X.md "Mode map kit format" v1. Rust `tools/editor/kits.rs` reads `<app dir>/kits/*.kit.json` itself
(validated against the format: schema, version ≤ 1, ids, reserved keys, types, draw, components `ls_*`, sizes; a bad file
is listed with a plain reason, never used), re-read only when a kit file changes. `GET /api/tools/editor/kits` →
`{folder, kits, bad, madeFor, key, needs}`.
- **Made for**: worldspawn key **`ls_modes`** = mode ids separated by spaces (saved in the project, exported in the .map
  and so in the .bsp). Set in Library > Mode kits (one undo step).
- **Live checks** for each made-for mode: `kit-needs` (marker/path/component count below min, with `place` =
  `<mode>:<marker id or classname>`; the Checks panel and the kit group show **Place**), `kit-too-many`, `kit-path` (one
  spot, repeated order), `kit-key` (number range, bool 0/1, choice, text ≤ 60), `kit-unknown` (made for a mode not
  installed). Warnings, never blocks. `Issue` gained an optional `place` field (checks.rs, `// P5`).
- **Library > Mode kits** (KitPanel.tsx; P4's LibraryPanel has a third tab): every installed kit as a group (the
  made-for ones first and open): what it still needs (Place), its markers (Spot/Area/Path, required counts, kit colour)
  and the components it uses, drag onto the map or Place. Placing uses P4's placing with ids `kit:<mode>:<id>`
  (extras.ts `placeComponentAt` hook): an `ls_marker` with `kind`, `mode`, the kit keys' defaults, an area's `size` or
  `radius`, a path's next `path`/`order`.
- **Form**: an `ls_marker`'s inspector comes from its kit (Marks, For mode, the marker's keys typed: number, choice
  lists, Yes/No, text; area size/radius; path/order) (EntityForm hook). **3D**: markers in their kit colour, areas as a
  wire box or a ring, paths as dashed lines in order (KitOverlay.tsx).
- **Creatures**: ls_creature's Type lists every type (built-ins + creatures.ini, which is where community creatures
  go) with its model preview; ls_wave_spawner gets creature-type toggles for its `types` key.
- **Playtest**: the made-for modes come first in the Mode list ("(made for)") and are picked when the last used mode
  isn't one of them (CompilePanel hook).
- **For X**: please make the kit's `mode.id` the same id start-options/modes.ini use (W1's notes say `laststand`, your
  example `last_stand`), so Playtest can match them. **For T (Publish)**: read `ls_modes` from the map's worldspawn
  (the .bsp entity lump) and mark the package as supporting those modes.
- Tests: kits.rs (format refusals; needs/too-many/path/key checks), `tests/editor-kits.spec.ts` (kit in the folder →
  Library group, Made for → ls_modes, needs + checks with place, Place → marker with keys, typed form, wrong key →
  warning, area size; creature types list and wave spawner toggles). Passed in Chromium and WebKit, with the assets and
  push specs.

**Mode uids in Made for (2026-11-13)**: kits may carry `mode.uid` (a UUID; checked when the kit is read). `ls_modes` is
now `uid:id,uid:id` (the short id only for showing); the old plain list (`last_stand royale`) still reads. A made-for
mode finds its kit by uid (so a renamed mode still matches and another mode with the same short id doesn't); old maps
(no uid) and old kits (no uid) match by short id; setting Made for again writes the uid. Kits are kept per uid. A mode
that isn't installed gets a plain note in Library > Mode kits and an Info check ("isn't installed here … Install it").
Playtest still compares short ids (the game's mode list has no uids yet). Tests: `made_for_by_uid_and_old_plain_ids`,
editor-kits.spec.ts (uid written, not-installed note, old plain id).
