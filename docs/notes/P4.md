## Done for QA (2026-11-12)
- **QA-1 fixed:** compiling looks for each WAD the map lists in this order: the path as written when it exists here
  (absolute), the path relative to the map's folder (`textures\\x.wad` style, `\\` or `/`), its name in the map's folder,
  then the game's folders. "The map's folder" is the project's, or the folder of the imported .map/.rmf/.jmf (the session
  keeps it: `Session.folder`, `install_from`, `editor::open_document_folder()`; saving a project somewhere else moves it).
  Found WADs are rewritten to real paths for SDHLT, copied next to the map when wine can't see them, and packed into the
  .bsp (`-wadinclude`) when they aren't stock, as before. The editor's texture list/sizes search the folder too.
  Test: `tools::compile::tests::wads_beside_the_project` (QA's `regamedll_zedit.wad` case, through the CrossOver layout).
- **QA-2 fixed:** an empty or non-WAD file is reported as "can't be read: gunshop.wad (it's empty (0 bytes))" instead of
  "not on this computer" (`wad_problem`, `Wads.bad`, `wad_errors`).
- **QA-3 fixed:** the missing-portal-file line becomes "The map has nothing inside it for the compiler to start from. Put a
  player spawn (info_player_start) inside a sealed room." (test `a_map_with_nothing_inside`).
- QA-4 (compile needs a Steam install for `servers::client`): left as is for the app; noted here for dev servers.
