Events

Game Mode Studio's Events nodes (44): what each does, its inputs and outputs, settings, limits and related nodes.

Made from the app's own catalog (nodes.json, nodehelp.json, limits.ts), so it always matches the app.

Round Started #

Runs when a round begins: freeze time is over and everyone can move.

The usual place to set a round up: give weapons, reset scores, show a message. It runs once per round for the whole server, not per player (use For Each Player for that).

Goes on when it's done.

Player Hurt #

Runs when a player takes damage, with the health it took (blocked damage doesn't count). Hit Position: where a bullet or the knife struck (else the middle of the victim); Direction: which way the hit was going (from the attacker). Use Get Transform on Victim/Attacker for where they were.

Runs after the damage is done, with what was really taken: nothing when it was blocked, less when armor took some. To change the damage before it lands, use Player About To Be Hurt.

Outputs

Goes on when it's done.

Attacker Player
Attacker: a player.
Damage Number
Health taken by this hit.
Headshot Yes/No
Yes when a bullet or the knife hit the head.
Health left Number
Health left after it (0 or less: the hit killed them).
Hit where Text
Where a bullet hit: head, chest, stomach, arm, leg; body for anything else (grenades, falls).
Weapon Text
The weapon that did it: the attacker's gun or knife, hegrenade for a grenade, empty when no player did it.
Hit Position Vector
Hit Position: a position or direction (X, Y, Z).
Direction Vector
Direction: a position or direction (X, Y, Z).

Cost: Runs on every hit, often many times a second in a firefight. Keep what follows it small.

Related: Player About To Be Hurt, Player Killed, Team Changed

Player Pressed Button #

Runs when a player presses (or lets go of) a button the game knows: fire, right click, use, jump, duck, reload, walk or a move key. It arrives with the player's ping, like everything they do. Only: wire a player (from a variable) to listen to one player only. Include bots: bots press buttons too.

Works the same on your own game, a listen server and a dedicated Linux server: the server sees a button when the player's game sends it, so it arrives with their ping (a 100 ms player's press shows up about 100 ms after they pressed). Only buttons the game itself has: fire, right click, use, jump, duck, reload, walk and the move keys. For any other key, use Player Command (players bind the key to it). Include bots: bots press buttons too (on by default); untick it for something only people should set off.

Inputs

Only this player Player
A player to listen to (from a variable, set when they're picked): nobody else's presses run it. Not wired: everyone's.

Outputs

Then Flow
Goes on when it's done.
Player Player
Who pressed it.
Button Text
Which button, by name: attack, attack2, use, jump, duck, reload, walk, forward, back, left, right.

Settings

Button
Pick one: Attack (fire), Attack 2 (right click), Use (E), Jump, Duck, Reload, Walk (Shift), Forward, Back, Move left, Move right, Any of these. Default: use. Choices: Attack (fire), Attack 2 (right click), Use (E), Jump, Duck, Reload, Walk (Shift), Forward, Back, Move left, Move right, Any of these.
When
Pick one: Pressed, Released. Default: pressed. Choices: Pressed, Released.
Include bots
On or off. Default: true.

Cost: A check of each player's buttons every server frame, only when a mode has this node; the flow runs only on a press.

Related: Is Holding Button, Player Command, Start Cooldown

Player Command #

Runs when a player uses a console command the mode names (ls_ and letters, like ls_dash): they can bind any key to it (bind f "ls_dash"). Arguments is the rest of the line, as text only: it's never run. Each player can use it at most a few times a second (Player Command uses a second, in the mode's Limits settings).

A key the game has no button for (F, G, a mouse button) can still start a flow: name a command (ls_ and letters, like ls_dash), and players bind a key to it in their console (bind f "ls_dash"); Tell Player To Bind shows them the line. Arguments is whatever came after the command, as text only: the mode can read it, but it's never run as a command. Player Command uses a second (each player) keeps a held or scripted key from flooding the server: a setting in the mode's Limits group, 5 to start (the checks warn above 20).

Outputs

Then Flow
Goes on when it's done.
Player Player
Who used the command.
Arguments Text
The rest of the line, as text (empty when there was none).

Settings

Command (ls_...)
A name, as the map or the game knows it (letters, digits, _ . -). Default: ls_dash.

Limits: Player Command uses a second (5 by default, hosts can raise it to 1000; slow above 20).

Careful: Safe by design: the command name can only be ls_ and letters (never one of the game's own), and the arguments are never run.

Related: Tell Player To Bind, Player Pressed Button, Chat Command
