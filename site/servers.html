Run a server on a VPS

Loner-Strike can set up an always-on server on a Linux machine you rent. It connects over SSH, installs Valve's server and Loner-Strike, and runs it as a service that keeps going when your computer is off.

You rent the machine, make an SSH key, open the game ports in the provider's firewall and fill in a form in the app. It takes 15 to 30 minutes, mostly waiting for downloads.

What you need

  • Loner-Strike on Windows, or on a Mac with the game in CrossOver (the server's plugins are built on your computer).
  • A machine with Ubuntu or Debian (Ubuntu 22.04 or 24.04 is safest) on an x86 (AMD or Intel) CPU, with a public IPv4 address.
  • Not Arm: Oracle Ampere A1, AWS Graviton, Hetzner CAX and Raspberry Pi can't run the Counter-Strike server.

1. Choose a host and size

Up to about 10, a few bots1 vCPU1 GB

The game uses one core, so a fast core beats many. About 2 GB of disk plus your maps.

  • Free: Oracle Cloud's Always Free AMD machines (VM.Standard.E2.1.Micro), when Oracle has capacity. Oracle's trial credits cover bigger machines for a while.
  • Paid: Hetzner, Vultr, DigitalOcean, OVH and Linode have small x86 plans. Pick a location near your players.

2. Make an SSH key

Mac or Linux, in Terminal:

mkdir -p ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/loner-strike -N "" -C loner-strike
cat ~/.ssh/loner-strike.pub

Windows 10 or 11, in PowerShell (press Enter twice when it asks for a passphrase):

mkdir $HOME\.ssh -Force
ssh-keygen -t ed25519 -f $HOME\.ssh\loner-strike -C loner-strike
Get-Content $HOME\.ssh\loner-strike.pub

The last line it prints, starting with ssh-ed25519, is the public key. Copy it for the next step. Keys with a passphrase aren't supported yet. A PuTTY key (.ppk) needs converting in PuTTYgen first (Conversions, then Export OpenSSH key).

3. Create the machine

  1. Create a new server (instance, droplet) with Ubuntu 24.04 or 22.04 on an x86 plan.
  2. Make sure it gets a public IPv4 address.
  3. Under SSH keys, paste the public key.
  4. Once it's running, note its public IP and SSH user: ubuntu on Oracle and AWS, root on Hetzner, DigitalOcean and Vultr.

Oracle Cloud

Shape: AMD, VM.Standard.E2.1.Micro (not Ampere). Turn on Assign a public IPv4 address; if it ends up without one, add an ephemeral public IP on the instance's VNIC (Attached VNICs, then IPv4 addresses, then edit). Firewall: the subnet's security list (Virtual cloud networks, your network, then Security). "Out of capacity" means no free machines there right now: try another availability domain, another shape, or later.

Hetzner Cloud

Shared vCPU x86 (CX or CPX), not Arm (CAX). Keep Public IPv4 on. No firewall by default; if you attach one (Firewalls), allow inbound UDP 27015-27020.

DigitalOcean

Any Basic droplet with Ubuntu. No firewall by default; if you use one (Networking, then Firewalls), add inbound UDP 27015-27020.

Vultr

Cloud Compute, an Intel or AMD plan. No firewall by default; if the server is in a firewall group (Network, then Firewall), add inbound UDP 27015-27020.

AWS Lightsail

Linux/Unix, OS only, Ubuntu. Upload your key under Change SSH key pair. Firewall: the instance's Networking tab, then IPv4 firewall and Add rule (Custom, UDP, 27015-27020). Attach a static IP so the address doesn't change when the instance restarts.

4. Open UDP 27015-27020

The app opens the ports in the machine's own firewall (iptables or ufw) during setup. It can't reach your provider's firewall (security list, security group, firewall group), so add an inbound rule there: protocol UDP, ports 27015-27020, source anywhere (0.0.0.0/0). Leave SSH (TCP 22) open; the app uses it for everything else.

5. Add it in Loner-Strike

  1. In Servers, choose New server and pick A Linux server (VPS).
  2. Address: the public IP. User: ubuntu or root.
  3. SSH key: Browse to the private key, the file without .pub. On a Mac, press Cmd+Shift+G in the picker and type ~/.ssh.
  4. Check the server. It shows the machine's fingerprint (SHA256:...) and whether it matches your computer's ~/.ssh/known_hosts. To check a new one, run ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub in your provider's web console and compare.
  5. Pick a name, the game, and Set it up like: My game (your modes, settings, admins and maps) or Start fresh.
  6. Who can join: Listed on Steam shows it in the server browser. Anyone with the address keeps it unlisted. A join password keeps strangers out either way.
  7. Make the server.

Setup takes 5 to 15 minutes. It installs the 32-bit libraries, opens the ports, downloads Valve's server with SteamCMD, installs Metamod-P, AMX Mod X and ReGameDLL, builds Loner-Strike on your computer, uploads it, and starts a service called lonerstrike-<name>. The server runs on UDP 27015, keeps running with the app closed and restarts after a crash or reboot.

6. Join and manage it

  • Join, Start, Stop and Open are in Servers. Join on a listed server works with the game open; on an unlisted one it restarts the game to connect.
  • Friends use connect <address>:27015 in the game console, or Find Servers if it's listed.
  • The server's Overview tab has its console, where you can send commands like status.

Over SSH (ssh -i ~/.ssh/loner-strike ubuntu@<address>), the lsctl helper manages it:

lsctl list        the servers on the machine
lsctl status      running or not
lsctl restart     also start, stop
lsctl logs        the last 100 console lines

Updating

  • The machine: sudo apt update && sudo apt upgrade, then sudo reboot if asked. The server starts again by itself.
  • Valve's server files: stop the server and press Update in its Maintenance panel. SteamCMD checks Valve's files on the machine; your settings, admins and stats stay.
  • Mods, plugins, maps and sounds: changes in the app reach the machine within a few seconds, and only what changed is sent. New plugins and maps load on the next map, or press Restart now on the server's page.
  • Wipe and rebuild: sets the server up again from scratch and wipes its folder on the machine first. Use it only when something is broken.

Troubleshooting

"Failed to contact game server"
The provider's firewall doesn't allow UDP 27015-27020 inbound, or the server is stopped.
Can't reach the machine on port 22
It's off, the address is wrong, or (on Oracle) it has no public IP.
The server didn't accept the key
Wrong user, the key wasn't added at creation, or you picked the .pub file.
The key has a passphrase
Not supported yet. Make one without a passphrase and add it to ~/.ssh/authorized_keys on the machine.
The server's identity has changed
Expected if you rebuilt the machine: run ssh-keygen -R <address> and add the server again. Otherwise, don't connect.
The machine is aarch64
It's an Arm machine. Make an x86 (AMD or Intel) one.
Setup stopped part way
Try again carries on where it stopped. Rebuild from scratch wipes the server's folder on the machine and starts over.

Removing it

Delete the server in the app; that stops the service and removes its folder on the machine. Then delete the machine at your provider so it stops costing money.
